# 当前代码的技术流程

当前应用代码、网页、模型和本地运行数据均位于仓库的 `top_camera/` 目录；下文路径相对于该目录。仓库根目录保留许可证和 Git 忽略规则。

## 1. 数据链路

```text
USB 摄像头
    ↓ 浏览器采集 JPEG
本机 Python HTTP 服务
    ├─ 校准：5 帧空场景 → 背景基准 + 黄色床框 → 人工确认
    └─ 检查：3 帧图像 → 人体关键点与分割
                           ├─ 相对姿势与短时移动判断
                           └─ 排除人体 → 可见背景差分
                                      ↓
                            合并结果 → ready / not ready
                                      ↓
                            网页叠加蓝框与红框
```

整个链路运行在连接摄像头的笔记本上，不经过 ACU、机器人或云端识别服务。

## 2. 空场景校准

`web/camera.js` 通过浏览器摄像头接口采集 5 帧；优先选择名称以 `Global` 开头的摄像头，否则使用默认设备。JPEG 最长采集宽度限制为 1280 像素，元数据保留实际视频尺寸。

`app.py` 接收图片后，`calibration.py` 将其缩小到不超过 480×360 像素，计算像素中值背景和帧间波动，形成背景参考与噪声阈值。过暗、过亮或明显不稳定的校准会被拒绝。

`bed_detection.py` 综合亮度阈值、边缘、形态学处理和轮廓矩形，寻找明亮、细长的床面，再根据长边的边缘响应修正床沿。程序只提出黄色床框，不自动认定其正确。用户确认床框、头端和空场景后，后端才启用基准。手动修正时也会根据像素长度区分长短边。

## 3. 姿势与短时稳定性

每次检查采集 3 帧。`positioning.py` 按床头方向旋转模型输入，通过本地 MediaPipe Full Pose Landmarker 得到 33 个关键点及人体分割；必要时重试曝光，输出坐标再转换回原图。

四个床角建立图像到床面归一化坐标的投影关系。姿势规则检查居中、头脚方向、身体偏斜、手臂位置、腿部状态及床沿范围；距离以本人肩宽和躯干长度归一化，不与样例人体轮廓重合。明显坐起使用单目深度提示与二维躯干缩短的组合启发式。

双臂放在躯干两侧、双臂举过头顶均可接受。规则容忍一定自然摆位、轻微旋转和关键点抖动；比较三帧关键点以拦截明显移动。至少两帧姿势通过且最后一帧通过，才能通过姿势分支。问题区域以蓝框返回；无法可靠观察也不放行。

## 4. 可见场景差分

根据人体分割生成排除掩码，适度扩展人体边缘，并用膝、踝位置补足容易遗漏的鞋子。排除范围不是整张床，也不是人体外接矩形。

`calibration.py` 在剩余可见背景中执行小幅几何对齐（ECC），将基准映射到当前图像坐标；再补偿整体曝光与局部缓慢光照。结合颜色保持情况和新增边缘，降低阴影、反光及原有床沿附近差异的影响。

差异图经过阈值化、形态学滤波和连通区域筛选，输出红框。最后一帧必须通过，三帧中也须至少两帧场景通过。可见背景不足时不放行。

## 5. 综合判定与保存

```text
最终 ready = 姿势及短时稳定性通过 AND 可见场景检查通过
```

`app.py` 返回综合状态、分支状态、归一化红蓝框与原因；`web/app.js` 在原始方向的照片上叠加显示。若姿态模型缺失或识别不可靠，不会退回“仅检查背景即可 ready”。

当前有效背景、噪声参数和床面参考保存在服务进程内存中，重启后需重新校准。磁盘保存校准快照，以及每次检查的最后一帧和结果 JSON；不保存完整三帧序列。历史检查按数量和空间上限清理。

## 6. 技术边界

这是单目 RGB 的固定场景演示。人体遮挡或被排除掩码覆盖的物品无法判断；光影容差会降低小型、低对比物品的检出能力。短时稳定性不等于持续监控，几何和深度启发式也不构成临床摆位认证。
